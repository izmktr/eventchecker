# イベントチェッカー

自分用のローカルWebアプリ。ESCAPE.IDとSCRAPチケットの公演URLから、基本情報・開催日時・空き状況を取り込みます。

## 起動

```powershell
npm install
npm run dev
```

ブラウザで http://127.0.0.1:3000 を開きます。別のポートを使う場合は `npm run dev -- --port 3001`。

## 画面

- **30日一覧**: 公演を縦、日付を横に表示。月・日の2段見出し。日付から日別、公演名・日程セルから公演詳細へ移動。
- **日別**: 公演ごとの時間軸。開催回をクリックすると、その日の購入状態を編集。
- **公演詳細**: 月別カレンダー、開催時刻、空き状況、購入済みチェック、販売ページへのリンク。
- **公演登録**: URLを入力して取り込み。同じ公演を再登録しても重複しません。

「購入済み」はこのアプリ内の記録です。販売サイトで購入・キャンセルを行う機能ではありません。
空き状況は取得時点の値です。更新ボタンで再取得し、失敗時は前回のデータと警告を表示します。

## 対応URLと取得方法

- 東京ミステリーサーカス: `https://ticket.mysterycircus.jp/index.php?dispatch=products.view&product_id=596` 形式。公開日付一覧と日付別カレンダーから最大186日分を取得。所要時間が掲載されている場合、終了時刻はその時間から算出した目安です。
- 既存のSupabaseを使う場合、東京ミステリーサーカスの登録前に `supabase/migrations/20260928_add_tmc.sql` をSQL Editorで実行してください（新規セットアップでは `schema.sql` に含まれています）。

- ESCAPE.ID: `https://escape.id/団体-org/e-公演/`。ページ内のAstroデータと、ページ自身が使う公開開催回一覧から取得。
- SCRAP: `https://scrapticket.jp/events/show/公演コード`。追跡用クエリは除外し、同じ公演の公開日程も取得。ページ内JSONと、未ログインで利用できる日付・時刻選択処理を使用。
- SCRAPの旧形式 `/events/?content_code=...` は未対応。開催日時を選択した後の `/events/show/` URLを使用してください。
- ログイン、購入、アクセス制限の回避は行いません。ページ形式の変更などで取得できない場合はエラーにします。
- 自動巡回はありません。取得は1件ずつ、SCRAPの日程リクエスト間に200msの間隔を設け、同一URLの更新は1分に1回までです。
- ESCAPE.IDは掲載期間の先頭から最大366日、SCRAPは公開された最大6か月・186日を取得。上限に達した場合は画面に表示します。
- SCRAPの拘束時間と各回の終了時刻は、URLが指す回の開始・終了時刻から算出した目安です。受付・移動時間は含みません。
- 表示はすべて日本時間。○・△・×以外に、販売期間外・決済待ち・不明を区別します。元サイトの表記も開催回に保持します。

指定の2公演を取り込むスクリプト:

```powershell
npx tsx scripts/import-examples.ts
```

## 保存先

`data/eventchecker.sqlite` に保存します。公演 (`events`)、開催回 (`sessions`)、個人の状態 (`user_events`)、購入済み開催回 (`reservations`) を別テーブルで管理。ローカルユーザーIDは `local` です。

再取得で購入記録は消えません。掲載がなくなった開催回も購入済みなら表示に残ります。公演の削除は確認画面を経て、その公演の購入記録も削除します。

バックアップする際はアプリを停止してから `data` フォルダー全体を保存してください。SQLiteのWALファイルが存在する場合も含めます。`EVENTCHECKER_DB` 環境変数で別の保存先を指定できます。

## Supabase / Vercel

`EVENTCHECKER_STORAGE=sqlite` でこれまでのローカル版、`supabase` でメール・パスワード認証付きクラウド版を使用します。現在の `.env.local` はローカル版を維持しています。Supabaseでテーブルと許可ユーザーを作成してから切り替えてください。

詳細は [Supabaseセットアップ](supabase/SETUP.md) を参照してください。Vercel上ではSQLiteへの自動フォールバックを行いません。現在の公演・購入記録は移行スクリプトで書き出せます。

サイトごとの取得処理は `lib/sources.ts`、ローカル保存処理は `lib/store.ts`、クラウド保存処理は `lib/supabase-store.ts` と `supabase/schema.sql` に分離しています。新サイト対応は共通の公演・開催回形式に変換する取得処理を追加します。
